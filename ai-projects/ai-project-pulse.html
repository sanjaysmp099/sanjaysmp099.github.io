The problem

Most portfolio projects from PM candidates are generic — a to-do app, a basic chatbot. They demonstrate that someone can call an API, but not that they understand how AI projects specifically go off track.

I wanted to build something that showed the opposite: that I know the failure modes unique to AI/ML delivery, and can turn that knowledge into a practical tool.

The approach

I scoped two focused tools rather than one broad one, both addressing real gaps I've seen in AI project delivery:

  • Risk & Timeline Assistant — takes a project description and surfaces AI-specific risks (data labeling delays, open-ended model evaluation cycles, vendor API limits, compliance review time) plus a realistic timeline breakdown with a recommended buffer.
  • Status Report Generator — takes messy raw notes (Slack threads, standup notes) and produces a structured weekly status report with a health indicator.

I built with Streamlit and Groq's free API (Llama 3.3 70B) specifically so the whole thing could be built and deployed at zero cost — an intentional constraint that also mirrors a real PM tradeoff: shipping something useful within a tight budget.

What makes it different

The core of this project isn't the chatbot interface — it's the domain knowledge encoded into the prompts. Each tool's system prompt is built around specific, named AI project failure modes rather than generic advice, so the output is something a real AI project team could actually use in planning or status meetings.

Example: instead of a generic "add buffer time" suggestion, the Risk & Timeline Assistant explains why a 20-30% buffer matters for AI projects specifically — model iteration cycles don't have a fixed "done" state the way typical software tasks do.

What I'd improve with more time

  • Add persistent storage so status reports can be tracked and compared across multiple weeks
  • Build a small eval set to measure whether the risk flags are actually accurate and useful versus generic, and iterate the prompts against that
  • Add export to PDF or a direct Slack post, so it fits into a real team's existing workflow instead of living as a standalone page

What this demonstrates

Scoping an MVP under real constraints, encoding subject-matter expertise into a tool's design rather than just wiring up an API call, and making practical judgment calls about what to build versus cut — the core of what AI project delivery actually requires.
